Coverage

room data, dungeon map packs and environment texture packs. The explicit snow
exception includes dun/item/main_data/icebig.img. Character, monster, menu and
general item directories are excluded, as recorded in the inventory.
5,244 texture occurrences; 2,124 distinct decoded pixel images.
24,234 drawable MDS object occurrences; 10,029 distinct mesh byte hashes.
Repeated day/night, scene, and LOD occurrences remain individually traceable.
The primary IMG extraction decoded every indexed entry without a decode error.
These counts are NOT counts of unique plants or independently placeable props.

Each model includes source container, MDS offset, object index/name, scene part,
material texture names, vertex/triangle counts, transformed bounds, geometry
preview and approximate horizontal/vertical area. Texture records include the
source offset, dimensions, pixel hash and preview. Geometry/material associations
help find ground/walls, but mixed atlases still require UV inspection. Standalone
TIM2 fallback names retain file/offset identity rather than invented asset names.

Integration policy
Texture names are only unique within their source scene. For example, e02b02
in gedit/e02/img.pak is grass, while the same name in gedit/s04/img.pak is a
sandy scene surface with a baked circular shadow. Runtime imported materials
must retain scene/name keys; bare-name maps silently replace ground materials
when additional assets load. Native model UVs resolve within their own scene.

Use assets where ecology, scale and original UVs fit. Retain a complete distant
representation for new woody/rock scatter. Reuse existing population candidates
and texture batches rather than adding unconstrained scatter layers. Keep vines
on supports and architectural pieces out of wilderness material palettes.
The catalogue is complete for its stated scanned environment scope; semantic
identification of every anonymous object is explicitly still incomplete.
